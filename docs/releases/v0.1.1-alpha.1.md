# Hephaestus `v0.1.1-alpha.1` Release Notes

Security-hardening alpha release remediating all 15 findings from the Daybreak security audit while preserving existing `hephaestus-core`, `hephaestus-store`, `hephaestus-store-sqlite`, and `hephaestus-store-object` public library contracts for downstream consumers.

## Security Remediation Summary

- **Release workflow privilege split & ancestry verification (#1):** `.github/workflows/release.yml` separates unprivileged `build` (`permissions: { contents: read }`) from gated `publish` (`contents: write`, `id-token: write`, `attestations: write`, `environment: release`), checks out full history (`fetch-depth: 0`), enforces `git merge-base --is-ancestor "${GITHUB_SHA}" refs/remotes/origin/main`, verifies the tag matches `Cargo.toml` `[workspace.package].version`, checks release notes presence, and pins all GitHub Actions by 40-hex commit SHA.
- **HTTP & Git smart-HTTP Bearer authentication & fail-closed bind policy (#2):** `hephaestus-server` requires `--http-auth-token-file` (loaded with `O_NOFOLLOW`, rejecting symlinked/non-regular files and group/world-accessible modes `(mode & 0o077) != 0`) verified with constant-time SHA-256 comparison across all non-`/health` HTTP and `/git/*` endpoints. Non-loopback HTTP binds refuse startup without `--http-auth-token-file`; loopback unauthenticated mode requires an explicit `--allow-unauthenticated-loopback-http` opt-in.
- **HTTP & Git smart-HTTP DoS hardening (#4):** Enforces global concurrency limits, request/response deadlines, strict body size bounds (`<= 64 MiB`), child `git` process deadlines (`kill_on_drop(true)`), and capped `stdout`/`stderr` streaming (`take(...)`) in both `hephaestus-server` and `hephaestus-jj`.
- **Single-pass changed-OID Git push indexing (#5):** `hephaestus-jj` replaces multiplicative per-bookmark full-tree snapshot materialization with single-pass deduplicated tree/blob traversal enforcing bookmark, file count, single-file, and aggregate unique byte budgets, committing catalog reference updates only after all budgets pass.
- **Authenticated LTX disaster-recovery restore & bounded Zstd decoding (#3, #9):** `hephaestus-store-sqlite` bounds Zstd decompression (`MAX_LTX_DECOMPRESSED_BYTES = 256 MiB` via `.take(limit + 1)`) and adds `restore_ltx_snapshot_zstd_verified(snapshot, dest_path, expected_digest, min_txid)` using constant-time BLAKE3 verification and monotonic `txid` enforcement. `hephaestus-server` requires verified digest checks (`--restore-ltx-digest`) and monotonic `last_restored_txid` tracking while preserving `restore_ltx_snapshot_zstd` for existing callers.
- **NixOS credential path & locked flake reproducibility (#6, #7):** `nix/modules/hephaestus.nix` switches `driveTokenFile` to `types.nullOr types.str` (never `types.path`), adds `httpAuthTokenFile` and `allowUnauthenticatedLoopbackHttp`, wires `systemd.services.hephaestus.serviceConfig.LoadCredential`, and enforces NixOS assertions rejecting `/nix/store/*` credential paths or unauthenticated non-loopback/firewall configurations. `flake.lock` locks flake inputs deterministically.
- **QUIC frame, stream, and aggregate memory caps (#8):** Bounds QUIC control/payload frames to `<= 16 MiB` (`MAX_QUIC_FRAME_BYTES`), validates expected binary payload before allocation, reads in capped chunks using `try_reserve`, enforces `64 MiB` aggregate inflight byte semaphore, `128` max connections, and a `60s` stream deadline.
- **SQLite read/verify connection isolation & paginated log verification (#10):** File-backed `SqliteStore` routes read/verify queries onto dedicated read-only (`SQLITE_OPEN_READ_ONLY | SQLITE_OPEN_NO_MUTEX`) connections with bounded semaphores (`read_sem = 16`, `verify_sem = 2`), enforces `DEFAULT_LOG_PAGE_LIMIT = 200` / `MAX_LOG_PAGE_LIMIT = 1000`, and streams Merkle/chain verification via `DecisionChainVerifier` and `ObservationChainVerifier`.
- **Canonical JSON duplicate-key rejection (#11):** `hephaestus-core::jcs::canonicalize_json` detects and rejects duplicate keys (including escaped Unicode equivalents) at all object nesting levels via `JcsError::DuplicateKey`.
- **Bundle directory & legacy Zstd bounds (#12, #13):** Enforces `MAX_BUNDLE_FRAMES`, `MAX_BUNDLE_DIR_BYTES`, `MAX_FRAME_COMP_BYTES`, `MAX_FRAME_RAW_DECODED_BYTES`, and `MAX_LEGACY_V1_DECODED_BYTES` in `hephaestus-core`, `hephaestus-store-object`, and `hephaestus-jj`, preventing `GRNB0002` buffers from silently falling back to `GRNB0001`.
- **Validated identifier deserialization (#14):** `RepoId`, `ChangeId`, `CommitId`, and `OpId` validate constructor invariants directly inside `serde::Deserialize`.
- **Sanitized client-facing errors (#15):** HTTP, QUIC, and Drive adapter errors scrub internal filesystem paths, OS errors, subprocess stderr, and upstream response bodies while logging structured opaque reference IDs server-side.

## Upgrade & Compatibility Notes

- **Server CLI & NixOS:** Operators starting `hephaestus-server` with an HTTP listener must supply `--http-auth-token-file <path>` (a `0400`/`0600` non-symlink secret file) or explicitly pass `--allow-unauthenticated-loopback-http` for local loopback-only development. NixOS users should set `services.hephaestus.httpAuthTokenFile` to a runtime credential path outside `/nix/store`.
- **API Compatibility:** All public types and traits used by downstream Rust integrators (`BlobDigest`, `SealedBundle`, `StoreError`, `CatalogStore`, `ObjectBackend`, `GoogleDriveStore`, `PackedCasEngine`, `DriveHttpClient`, `GOOGLE_DRIVE_BASE_URL`, `SqliteStore`, `LTX_SNAPSHOT_MAGIC`, `restore_ltx_snapshot_zstd`, `RepoId`, `CommitId`, `ChangeId`, `OpId`) retain backwards-compatible signatures alongside the new `*_verified` APIs.
